# Sova: дизайн

Значок-глаз в строке меню. Не даёт MacBook уснуть при закрытой крышке, пока работают ИИ-агенты. Заменяет форк Insomnia (16 тысяч строк). Цель: около 500 строк кода, 10–15 содержательных тестов, 0% процессора в простое, не больше 3% во время сессии.

## Решения Александра (31.10.2026)

- Новая папка и новый git: `~/Documents/Вайбкодинг/Программы macos/Sova`. На GitHub не выкладываем без отдельной команды.
- Имя: **Sova**. Bundle id `com.ungurenko.sova`.
- Заряд ниже **15%** без зарядки: сессия заканчивается.
- Перегрев: «критический» заканчивает сессию сразу, «серьёзный» дольше 5 минут тоже.
- Потолок сессии 8 часов, кнопки «без ограничения» нет.

## Чего в программе нет

Раздачи интернета, заморозки программ, притормаживания браузеров, Docker, яркости, звука, окна настроек, анимаций в значке, запуска при входе в систему (добавляется позже одной галочкой, если понадобится), продления сессии кнопкой (выбор длительности заново сам перезапускает отсчёт).

## Как это выглядит (пример использования)

Клик по глазу открывает меню:

```
Не спит ещё 2:41:05            ← или «Сон работает как обычно»
─────────────
Не давать спать:
   30 минут · 1 час · 2 часа · 4 часа · 8 часов
Остановить                      ← только во время сессии
─────────────
Заряд 87%, от батареи           ← только на ноутбуке
Последняя сессия: заряд упал ниже 15%
─────────────
Выйти из Sova
```

Если запуск сессии не удался (например, нет разрешения), всплывает окно с причиной и подсказкой запустить `scripts/install.sh`.

Значок: закрытый глаз (ресницы снизу) в покое, открытый глаз (зрачок, ресницы сверху) во время сессии. Рисуется один раз в шаблонную картинку, без покадровой анимации.

## Карта модулей

Два модуля SwiftPM. Решения лежат в `SovaCore` (без AppKit, тестируется), связь с системой в `Sova`.

```

  SleepHold.swift      единственное место, где трогается root          (~90 строк)
  Controller.swift     состояние сессии, один таймер                   (~90 строк)

  main.swift           запуск, сигналы, аргумент --seconds             (~50 строк)

  StatusMenu.swift     значок и меню                                   (~100 строк)

Tests/SovaCoreTests/   Rules, SleepHold, Controller

```

### Rules.swift (чистая логика)

```swift
enum StopReason: Equatable { case finished, manual, lowBattery(percent: Int), overheated, quit }
struct Battery: Equatable { var percent: Int; var onBattery: Bool }   // на настольном Маке батареи нет → nil

enum Verdict: Equatable {
    case keep(recheckAt: Date)      // когда надо посмотреть снова, даже если событий не будет
    case stop(StopReason)
}

struct Rules {
    static let batteryFloor = 15                 // стоп при percent < 15 и onBattery
    static let seriousHeatGrace: TimeInterval = 300
    static let durations: [(label: String, seconds: TimeInterval)]   // 30 минут … 8 часов
    let endsAt: Date
    private(set) var hotSince: Date?             // с какого момента «серьёзный» или «критический»
    mutating func thermalChanged(_ state: ProcessInfo.ThermalState, at: Date)
    func verdict(at now: Date, battery: Battery?, thermal: ProcessInfo.ThermalState) -> Verdict
}
func countdownText(_ seconds: TimeInterval) -> String   // «2:41:05»
```

Порядок проверок в `verdict`: время вышло → `.finished`; `.critical` → `.overheated`; жар не спадает 5 минут → `.overheated`; батарея на разряде ниже 15% → `.lowBattery`; иначе `.keep(recheckAt: min(endsAt, hotSince+300))`.

### SleepHold.swift (root и журнал)

```swift
protocol SleepHold {
    func engage(until: Date) throws   // журнал → pmset 1 → сверка чтением
    func release() throws             // pmset 0 → удалить журнал; если pmset упал, журнал остаётся
    func recoverLeftover()            // при старте: журнал остался от прошлого запуска → release()
}
struct PmsetHold: SleepHold {
    init(journal: URL, run: @escaping (String, [String]) throws -> (status: Int32, output: String))
}
```

Порядок важен для надёжности: журнал (`~/Library/Application Support/Sova/session`, одна строка: время конца в секундах от 1970) пишется **до** включения настройки и удаляется **после** её выключения. Тогда сбой в любой точке не оставляет настройку без следа. Единственная команда с root: `/usr/bin/sudo -n /usr/bin/pmset -a disablesleep 1|0` с таймаутом 10 секунд.

### Controller.swift

```swift
@MainActor final class SessionController {
    enum State: Equatable { case idle(last: Outcome?), active(endsAt: Date) }
    struct Outcome: Equatable { var reason: StopReason?; var error: String? }
    private(set) var state: State
    var onChange: () -> Void
    init(hold: SleepHold, now: @escaping () -> Date, battery: @escaping () -> Battery?,
         thermal: @escaping () -> ProcessInfo.ThermalState, notify: @escaping (String) -> Void)
    func start(seconds: TimeInterval)   // новая сессия, старая заменяется
    func stop()                          // вручную
    func conditionsChanged()             // вызывают события батареи, температуры, пробуждения и таймер
    func shutdown()                      // выход из программы: вернуть сон
}
```

Один таймер: после каждого изменения ставится на `recheckAt`. В простое таймеров нет совсем.

### Система вокруг

- Батарея: `IOPSNotificationCreateRunLoopSource`, срабатывает только когда меняется процент или включают зарядку.
- Температура: `ProcessInfo.thermalStateDidChangeNotification`.
- Пробуждение: `NSWorkspace.didWakeNotification` → `conditionsChanged()`.
- Меню: секундный таймер работает **только пока меню открыто** (`menuWillOpen` / `menuDidClose`).
- Сигналы SIGTERM/SIGINT/SIGHUP → `shutdown()`.
- Уведомления: `UNUserNotificationCenter`, только при автоматическом конце (время, батарея, перегрев).

## Сторож (защита от падения)

`~/Library/LaunchAgents/com.ungurenko.sova.guard.plist` запускает `guard.sh` при входе и каждые 60 секунд. Скрипт ничего не проверяет по подписям и не запускает Sova.

```
нет файла session                 → выйти, ничего не трогать (чужую настройку не касаемся)
время конца в будущем И Sova жива → выйти
иначе                             → sudo -n pmset -a disablesleep 0, удалить файл, дописать строку в ~/Library/Logs/Sova.log
```

Контракт между программой и сторожем один: формат файла `session` (число секунд, одна строка). Скрипт в тестах получает подмену `pmset` и путь к папке через переменные окружения.

## Права

Один раз: файл `/etc/sudoers.d/sova` с двумя строками для `pmset -a disablesleep 1` и `pmset -a disablesleep 0` (аргументы прописаны целиком, шаблонов нет). Ставит `install.sh` через системное окно пароля (`osascript ... with administrator privileges`), проверка `visudo -cf` до установки, файл собирается и проверяется от root в `mktemp`, поэтому подменить его до установки нельзя.

## Рассмотрено и отброшено

- **B. Сторож внутри сессии**: программа запускает дочерний скрипт, который следит за ней и возвращает сон. Не закрывает перезагрузку и отключение питания, всё равно нужна служба. Отброшено.
- **C. Всё в одном файле, без чистых правил** (как Sleepless). Нечего тестировать, решения про заряд и жар прячутся в кнопках. Отброшено.
- **D. Служба с правами администратора и связью по XPC** (как Lidless). Нужны подпись разработчика, одобрение в настройках и втрое больше кода. Отброшено.
- Выбрано **A**: `Rules` (решения) отдельно от `SleepHold` (root) и от интерфейса. Служба — крошечный скрипт без зависимостей.

## Известные ограничения (по итогам независимой проверки 31.10.2026)

- **Перезагрузка посреди сессии.** Сторож работает от имени пользователя и запускается после входа в систему. Если Мак перезагрузился при включённой настройке (сбой, отключение питания) и ждёт пароль на экране входа, сон вернётся только после входа. Системная служба с правами администратора закрыла бы это, но добавляет файл от root и больше кода. Не делаем, пока не понадобится.
- **Зависший sudo.** Команды `pmset` выполняются в главном потоке с таймаутом 10 секунд. Если sudo завис, меню замирает до 10 секунд на вызов. В обычной работе вызов занимает миллисекунды.
- **Гонка сторожа и новой сессии.** Если сторож действует ровно в миллисекунды, когда пользователь запускает новую сессию, сторож может вернуть сон при «активной» сессии. Мак при этом уснёт, это безопасная сторона. Журнал новой сессии сторож не стирает (проверяется тестом).
- **Исправлено по проверке:** журнал не стирается, если после неудачного включения сон остался выключенным (хранитель читает настоящее состояние через `pmset -g`); неудачная замена идущей сессии сбрасывает старый таймер; `--seconds` принимает только 1…28800; установка ждёт реального выхода старой копии и повторяет загрузку службы; удаление выполняет всё от администратора одной командой и ничего не стирает, если сон вернуть не удалось.

## Тесты (содержательные)

Rules: (1) в пределах времени держим, `recheckAt` = конец; (2) по концу времени `.finished`; (3) 15% держим, 14% на разряде стоп; (4) 10% на зарядке держим; (5) настольный Мак без батареи; (6) `.critical` стоп сразу; (7) «серьёзный» 4:59 держим, 5:00 стоп, `recheckAt` = hotSince+300; (8) жар спал за 4 минуты, счётчик сброшен; (9) `countdownText`.
SleepHold: (10) журнал создаётся до `pmset 1`; (11) `pmset 1` упал при выключенной настройке, журнала нет; (12) `pmset 1` упал, но сон уже выключен прошлой сессией, журнал помечен «0» для сторожа; (13) macOS проигнорировала включение, сессия не объявляется; (14) `pmset 0` упал, журнал остался и помечен «0»; (15) `recoverLeftover` возвращает сон.
Controller: (16) заряд упал, сессия закончена, уведомление ушло; (17) старт с пустой батареей; (18) `engage` упал, состояние покоя с текстом ошибки; (19) неудачная замена идущей сессии сбрасывает таймер; (20) ручная остановка и выход тихие; (21) `release` упал, об этом сообщено громко.
Сторож (shell, `scripts/test-guard.sh`): семь случаев: нет файла, идёт сессия, время вышло, программа мертва, журнал «0», sudo отказал, новая сессия началась во время работы сторожа.

## Как проверяем «готово» на реальном Маке

1. `./scripts/install.sh`, один раз пароль в системном окне.
2. Простой: `top -l 5 -pid <pid>` показывает около 0%.
3. Сессия `--seconds 90`: `pmset -g` показывает `SleepDisabled 1`, процессор не выше 3%, после конца `SleepDisabled 0`, файл `session` удалён.
4. Падение: сессия, `kill -9`, через 60–70 секунд `SleepDisabled 0` и строка в `Sova.log`.
5. Крышка: сессия, фоновый скрипт пишет метку времени каждые 5 секунд, Александр закрывает крышку на 2 минуты. В метках нет дыр, в `pmset -g log` нет сна.
6. Старый Insomnia удаляется только после слова Александра (служба, правило sudoers, программа).
